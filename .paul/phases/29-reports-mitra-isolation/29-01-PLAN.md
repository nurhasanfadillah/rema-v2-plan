<objective>
## Goal
Enforce data isolation untuk role mitra di halaman Laporan — mitra hanya melihat orders dan ledgers milik dirinya sendiri.

## Purpose
Bug aktif di production: mitra bisa melihat data semua mitra di halaman Laporan. Ada dua root cause — backend tidak enforce filter by role, dan frontend timing bug menyebabkan filter selalu `'all'`.

## Output
- `orders.ts` dan `ledgers.ts`: GET / otomatis filter by mitra jika role adalah `mitra`
- `Reports.tsx`: filter `finMitraId` dan `ordMitraId` ter-set benar via `useEffect` setelah `mitras` load
</objective>

## AC-1: Backend Enforce Mitra Filter
```gherkin
Given user login sebagai mitra (JWT role = 'mitra')
When GET /api/orders atau GET /api/ledgers dipanggil (dengan atau tanpa query param)
Then response hanya berisi data milik mitra tersebut (berdasarkan userId dari JWT)
```

## AC-2: Admin Tidak Terpengaruh
```gherkin
Given user login sebagai admin atau staff
When GET /api/orders atau GET /api/ledgers dipanggil
Then response tetap berisi semua data (behavior lama tidak berubah)
```

## AC-3: Frontend Filter Ter-set Benar
```gherkin
Given user login sebagai mitra dan halaman Laporan dibuka
When data mitras selesai di-load dari API
Then filter finMitraId dan ordMitraId ter-set ke mitraId milik user tersebut (bukan 'all')
```

<task type="auto">
  <name>Task 1: Backend — Enforce mitra filter di orders dan ledgers API</name>
  <files>src/api/routes/orders.ts, src/api/routes/ledgers.ts</files>
  <action>
    Di kedua file, modifikasi handler GET / untuk enforce filter berdasarkan role:

    **orders.ts GET /**
    1. Tambah import `mitras` dari schema: `import { orders, orderItems, mitras } from '../../db/schema.ts'`
    2. Sebelum query orders, cek `req.user.role`:
       - Jika `'mitra'`: query `db.select().from(mitras).where(eq(mitras.userId, req.user.sub)).limit(1)` untuk dapat `mitraId`
       - Jika mitra tidak ditemukan, return `res.status(403).json({ error: 'Mitra not found' })`
       - Override `mitraId` dari query param dengan mitraId dari lookup — mitra tidak boleh memilih mitraId sendiri
       - Jika role lain (`admin`, `staff`, `operational`): pakai `mitraId` dari query param seperti semula

    **ledgers.ts GET /**
    1. Tambah import `mitras` dari schema: `import { and, eq, desc } from 'drizzle-orm'` sudah ada; tambah `mitras` ke schema import
    2. Logika sama dengan orders.ts — jika role `'mitra'`, lookup mitraId by userId, enforce filter

    Pattern yang benar untuk kedua file:
    ```ts
    router.get('/', async (req: Request, res: Response) => {
      try {
        let filterMitraId = req.query.mitraId as string | undefined;
        
        if (req.user.role === 'mitra') {
          const [mitra] = await db.select().from(mitras).where(eq(mitras.userId, req.user.sub)).limit(1);
          if (!mitra) return res.status(403).json({ error: 'Mitra not found' });
          filterMitraId = mitra.id; // override — tidak bisa dimanipulasi dari query param
        }
        
        // lanjutkan query dengan filterMitraId
      }
    });
    ```

    Hindari: menggunakan `req.query.mitraId` langsung untuk role mitra — itu yang menyebabkan vulnerability.
  </action>
  <verify>
    `npm run lint` tidak ada error TypeScript.
    Secara logika: trace path untuk role `mitra` — harus selalu filter by mitraId dari DB, bukan dari query param.
  </verify>
  <done>AC-1 dan AC-2 satisfied: mitra hanya dapat data miliknya, admin/staff tidak terpengaruh</done>

<task type="auto">
  <name>Task 2: Frontend — Fix timing bug filter mitra di Reports.tsx</name>
  <files>src/pages/Reports.tsx</files>
  <action>
    Masalah: `finMitraId` dan `ordMitraId` diinisialisasi via `useState` saat `mitras` masih `[]` (async belum selesai), sehingga `.find()` selalu return `undefined` → fallback ke `'all'`.

    Fix: Tambah `useEffect` yang watch `[mitras, user]` dan set filter ke mitraId yang benar setelah data load.

    1. Hapus inisialisasi conditional yang broken di baris 32-37:
    ```tsx
    // HAPUS ini:
    const [finMitraId, setFinMitraId] = useState<string>(user?.role === 'mitra' ? mitras.find(m => m.userId === user?.id)?.id || 'all' : 'all');
    const [ordMitraId, setOrdMitraId] = useState<string>(user?.role === 'mitra' ? mitras.find(m => m.userId === user?.id)?.id || 'all' : 'all');
    ```

    2. Ganti dengan inisialisasi default `'all'`:
    ```tsx
    const [finMitraId, setFinMitraId] = useState<string>('all');
    const [ordMitraId, setOrdMitraId] = useState<string>('all');
    ```

    3. Tambah `useEffect` baru setelah useState declarations (setelah baris deklarasi state, sebelum `useEffect` yang load data):
    ```tsx
    useEffect(() => {
      if (user?.role === 'mitra' && mitras.length > 0) {
        const myMitra = mitras.find(m => m.userId === user.id);
        if (myMitra) {
          setFinMitraId(myMitra.id);
          setOrdMitraId(myMitra.id);
        }
      }
    }, [mitras, user]);
    ```

    Tidak perlu ubah UI — dropdown filter mitra sudah hidden untuk role mitra (hanya tampil untuk `admin`).
  </action>
  <verify>
    `npm run lint` tidak ada error TypeScript.
    Secara logika: saat `mitras` ter-load (dari `[]` ke array berisi data), `useEffect` akan trigger dan set filter ke mitraId yang benar.
  </verify>
  <done>AC-3 satisfied: filter finMitraId dan ordMitraId ter-set benar setelah mitras load</done>
</task>
