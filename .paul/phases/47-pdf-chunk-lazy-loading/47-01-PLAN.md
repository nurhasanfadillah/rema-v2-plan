<objective>
## Goal
Chunk `@react-pdf/renderer` (±1,47 MB / 492 kB gzip) tidak lagi dimuat saat startup untuk semua pengguna; hanya diminta ketika halaman yang memakainya (Laporan, Detail Pesanan) dibuka. Permintaan dari sesi induk, berdasarkan temuan discovery fitur ekspor PDF Mitra (Phase 46); perbaikan chunking ini independen dari fitur tersebut.
</objective>

<context>
@.paul/phases/32-code-audit-cleanup/32-01-SUMMARY.md (tujuan Phase 32: isolasi `vendor-pdf` + `vendor-charts` dari initial bundle)
@vite.config.ts
@src/App.tsx (halaman berat sudah `React.lazy`)
</context>

<acceptance_criteria>

## AC-1: Chunk PDF tidak di jalur kritis
Given build produksi (`npm run build`)
When `index.html` hasil build dan awal file entry `index-*.js` diperiksa
Then tidak ada `<link rel="modulepreload">` ke chunk react-pdf dan entry tidak meng-import chunk itu secara statis (nama chunk boleh muncul di array `__vite__mapDeps`)
And hanya halaman yang memakai `@react-pdf/renderer` (Reports, OrderDetail) yang meng-import chunk itu secara statis

## AC-2: Ukuran dan kualitas terjaga
Given perubahan selesai
When build baseline dan build sesudah diukur
Then ukuran entry berbeda ≤ ±1 kB dari baseline
And `vendor-charts` tidak berubah, `npm run lint` lulus, dan precache PWA praktis sama

## AC-3: PDF tetap dihasilkan dan chunk dimuat saat dibutuhkan
Given build produksi dijalankan lewat `vite preview`
When Laporan › Cetak PDF (Keuangan, Pesanan, Rekap Tagihan) dan Detail Pesanan › Cetak SPK / Resi Offline dipakai
Then masing-masing menghasilkan file PDF valid
And chunk PDF baru diminta saat halaman itu dibuka, bukan saat startup (Login/Dashboard)

</acceptance_criteria>

<tasks>

<task type="auto">
  <name>Hapus entri 'vendor-pdf' dari manualChunks di vite.config.ts</name>
  <files>vite.config.ts</files>
  <action>
    Di `build.rollupOptions.output.manualChunks` hapus `'vendor-pdf': ['@react-pdf/renderer']`; biarkan `'vendor-charts': ['recharts']` (Dashboard memakai recharts, memang eager). Tambahkan komentar singkat alasan entri itu tidak boleh dikembalikan.
    Penyebab: manualChunks bentuk objek ikut menarik modul bersama chunk-nya — `react/jsx-runtime` (`j`) masuk `vendor-pdf`, sehingga entry dan semua halaman lazy meng-import chunk 1,47 MB itu secara statis dan Vite men-preload-nya di `index.html`.
    Catatan: perubahan dikerjakan dan diukur dulu oleh sesi samping atas permintaan sesi induk, lalu dicatat lewat PAUL (pola sama dengan Phase 45).
    Avoid: mengubah `vendor-charts`, dependency (`package.json`), komponen PDF (`src/components/**/*PDF*`), halaman Reports/OrderDetail, atau fitur ekspor PDF Mitra (Phase 46).
  </action>
  <verify>
    1. Build baseline (config lama) dan build sesudah ke direktori scratch di luar `dist/`: `npm run build -- --outDir node_modules/.cache/<nama> --emptyOutDir`; catat ukuran chunk, `index.html`, awal entry, dan precache PWA.
    2. `npm run lint` — exit 0.
    3. `vite preview --outDir <scratch sesudah>` + mock API lokal: Login/Dashboard tanpa permintaan chunk PDF; buka Laporan dan Detail Pesanan → chunk PDF diminta; semua tombol Cetak PDF menghasilkan PDF valid.
    4. Hapus direktori scratch.
  </verify>
  <done>AC-1, AC-2, AC-3 satisfied; hasil ukur sebelum/sesudah dicatat di SUMMARY.</done>
</task>
