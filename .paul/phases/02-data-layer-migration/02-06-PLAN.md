<objective>
## Goal
Migrasi Mitras.tsx dan CancellationsReturns.tsx dari localStorage ke API — hapus semua `db.*` calls, ganti dengan `api.*` async calls.

## Purpose
Dua halaman ini adalah manajemen mitra (CRUD lengkap + statistik) dan pembatalan/retur pesanan (mutasi multi-entity: order + ledger + request). Setelah plan ini, hanya Finance.tsx dan orders/* yang tersisa.

## Output
- `Mitras.tsx` — full async: load via useEffect, semua mutasi via api.mitras.* + api.auditLogs.*
- `CancellationsReturns.tsx` — full async: load via useEffect, handleSubmit via api.orders.* + api.ledgers.* + api.requests.* + api.auditLogs.*
- `DELETE /api/mitras/:id` — permanent delete dengan 4-layer validation (orders, ledgers, requests, linked user cascade)
- `DELETE /api/ledgers/order/:orderId` — hapus ledger entries terkait satu pesanan (dibutuhkan untuk rollback saat cancel/return)
- `api.ledgers.removeByOrder()` di api.ts
</objective>

    **A. Fix DELETE /api/mitras/:id di mitras.ts:**

    Endpoint saat ini hanya set isArchived=true. Ubah menjadi permanent delete dengan validasi:
    1. Cek apakah mitra punya orders (by mitraId) → jika ada, return 409 `{ error: 'Mitra memiliki data pesanan, tidak dapat dihapus' }`
    2. Cek apakah mitra punya ledger entries (by mitraId) → jika ada, return 409
    3. Cek apakah mitra punya requests (by mitraId) → jika ada, return 409
    4. Ambil mitra record untuk mendapat userId (linked user)
    5. Jika ada linkedUser (userId), delete user tersebut dari tabel users
    6. Delete mitra dari tabel mitras
    7. Return 200 `{ success: true }`

    Import yang dibutuhkan: `{ mitras, orders, ledgers, requests, users }` dari schema, `{ eq }` dari drizzle-orm.
    Ikuti pola 409 guard dari src/api/routes/users.ts.
