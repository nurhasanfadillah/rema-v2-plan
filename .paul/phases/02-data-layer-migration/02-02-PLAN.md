<objective>
## Goal
Buat client-side API wrapper (`src/lib/api.ts`) dan migrasikan semua auth layer (AuthContext, Login, ChangePassword) dari `localStorage + db.*` ke API calls dengan JWT token.

## Purpose
Phase 2 harus mengganti semua `db.*` calls dengan API calls. Plan ini menangani fondasi (api.ts + Vite proxy) dan layer auth yang paling kritis — setelah ini Plan 02-03 bisa mengganti semua halaman lain secara sistematis.

## Output
- `src/lib/api.ts` — typed client wrapper untuk semua 7 entitas + auth
- `vite.config.ts` — proxy `/api` → `http://localhost:3001` untuk dev
- `src/context/AuthContext.tsx` — JWT token-based, user di-fetch dari `/api/auth/me`
- `src/pages/Login.tsx` — calls `POST /api/auth/login`
- `src/pages/ChangePassword.tsx` — calls `PATCH /api/users/:id/password`
- `src/api/routes/users.ts` — ditambah `PATCH /:id/password` endpoint
</objective>

## AC-1: API client mengirim request dengan auth header
```gherkin
Given src/lib/api.ts diimport dan token tersimpan di localStorage key 'rema_token'
When method api.mitras.list() dipanggil
Then fetch ke GET /api/mitras dikirim dengan header Authorization: Bearer <token>
  And jika response non-2xx, throw Error dengan pesan dari response JSON .error
```

## AC-2: Login menggunakan API
```gherkin
Given halaman Login
When admin memasukkan nomor HP dan password yang valid lalu submit
Then POST /api/auth/login dipanggil
  And token dari response disimpan di localStorage key 'rema_token'
  And user object dari response disimpan di AuthContext state
  And tidak ada lagi panggilan ke db.getUsers() atau localStorage langsung di Login.tsx
```

## AC-3: Sesi bertahan setelah page refresh
```gherkin
Given user sudah login (token ada di localStorage 'rema_token')
When halaman di-refresh
Then AuthContext memanggil GET /api/auth/me menggunakan token tersimpan
  And jika berhasil, user state diisi dari response
  And jika gagal (401/expired), token dihapus dan user state null
  And db.getUsers() tidak dipanggil sama sekali
```

## AC-4: Password change berfungsi via API
```gherkin
Given user sudah login dan membuka halaman ChangePassword
When user submit password baru (dengan old password jika bukan forced)
Then PATCH /api/users/:id/password dipanggil dengan { oldPassword?, newPassword }
  And server memverifikasi oldPassword dengan bcrypt.compare (jika bukan mustChangePassword)
  And jika berhasil, user state di AuthContext diupdate dengan data terbaru
  And db.saveUsers() tidak dipanggil
```

    **Buat src/lib/api.ts:**

    Token management (internal helpers):
    - `getToken()` → `localStorage.getItem('rema_token')`
    - `setToken(t)` → `localStorage.setItem('rema_token', t)`
    - `clearToken()` → `localStorage.removeItem('rema_token')`

    Internal `request<T>(method, path, body?)` helper:
    - Base URL: `/api` (hardcoded, Vite proxy handles dev, Vercel same-origin prod)
    - Selalu tambah `Content-Type: application/json`
    - Jika token ada, tambah `Authorization: Bearer <token>`
    - Jika response not ok, parse JSON lalu throw Error dengan field `.error` atau response.statusText

    Export `api` object dengan shape berikut (semua typed pakai TypeScript types dari `../types`):
    ```
    api.auth.login(phone, password) → POST /auth/login → { token, user }
    api.auth.me()                   → GET  /auth/me    → { user }
    api.auth.setToken(t)            → wrapper setToken
    api.auth.clearToken()           → wrapper clearToken
    api.auth.getToken()             → wrapper getToken

    api.mitras.list()               → GET    /mitras
    api.mitras.create(data)         → POST   /mitras
    api.mitras.update(id, data)     → PUT    /mitras/:id
    api.mitras.remove(id)           → DELETE /mitras/:id

    api.products.list()             → GET  /products
    api.products.create(data)       → POST /products
    api.products.update(id, data)   → PUT  /products/:id

    api.users.list()                → GET /users
    api.users.create(data)          → POST /users  (body: { password, ...rest })
    api.users.update(id, data)      → PUT  /users/:id
    api.users.changePassword(id, body) → PATCH /users/:id/password

    api.orders.list()               → GET  /orders
    api.orders.create(data)         → POST /orders
    api.orders.update(id, data)     → PUT  /orders/:id

    api.ledgers.list(mitraId?)      → GET  /ledgers?mitraId=X (jika mitraId diberikan)
    api.ledgers.create(data)        → POST /ledgers

    api.requests.list()             → GET /requests
    api.requests.create(data)       → POST /requests
    api.requests.update(id, data)   → PUT  /requests/:id

    api.auditLogs.list(limit?)      → GET /audit-logs?limit=N
    api.auditLogs.create(data)      → POST /audit-logs
    ```

    Untuk return type `api.auth.login`: `Promise<{ token: string; user: Omit<User, 'passwordHash'> }>`

    User yang dikembalikan API tidak punya field `passwordHash` — gunakan `Omit<User, 'passwordHash'>` atau buat local type.

    **Update src/api/routes/users.ts — tambah PATCH /:id/password:**

    Tambah route setelah PUT /:id:
    ```
    router.patch('/:id/password', async (req: AuthRequest, res: Response) => {
      const { oldPassword, newPassword } = req.body;
      if (!newPassword) return res.status(400).json({ error: 'newPassword wajib diisi' });

      const [user] = await db.select().from(users).where(eq(users.id, req.params.id)).limit(1);
      if (!user) return res.status(404).json({ error: 'User not found' });

      // Jika oldPassword diberikan, verifikasi dulu
      if (oldPassword !== undefined) {
        const match = await bcrypt.compare(oldPassword, user.passwordHash);
        if (!match) return res.status(401).json({ error: 'Kata sandi lama tidak sesuai.' });
      }

      const [updated] = await db.update(users)
        .set({ passwordHash: await bcrypt.hash(newPassword, 12), mustChangePassword: false })
        .where(eq(users.id, req.params.id))
        .returning();

      const { passwordHash, ...safe } = updated;
      return res.json(safe);
    });
    ```
    Wrap dalam try/catch dengan `res.status(500).json({ error: err.message })`.
