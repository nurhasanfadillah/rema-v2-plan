<task type="auto">
  <name>Task 1: Fix vercel.json + update CORS untuk production</name>
  <files>vercel.json, src/api/index.ts</files>
  <action>
    **A. Update vercel.json:**

    Perluas `includeFiles` dari `src/db/**` ke `src/**` agar semua source
    API ter-bundle (routes, middleware, db):

    ```json
    {
      "rewrites": [
        { "source": "/api/(.*)", "destination": "/api" }
      ],
      "functions": {
        "api/index.ts": {
          "includeFiles": "src/**",
          "maxDuration": 30
        }
      }
    }
    ```

    `maxDuration: 30` diperlukan karena R2 upload dan DB query bisa >10s
    pada cold start serverless.

    **B. Update CORS di src/api/index.ts:**

    Ganti baris CORS saat ini:
    ```typescript
    app.use(cors({ origin: process.env.CORS_ORIGIN || 'http://localhost:3000' }));
    ```
    Dengan:
    ```typescript
    const allowedOrigins = (process.env.CORS_ORIGIN || 'http://localhost:3000')
      .split(',')
      .map(o => o.trim());
    app.use(cors({
      origin: (origin, callback) => {
        if (!origin || allowedOrigins.includes(origin)) {
          callback(null, true);
        } else {
          callback(new Error('Not allowed by CORS'));
        }
      },
    }));
    ```

    Ini memungkinkan CORS_ORIGIN berisi multiple origin dipisah koma,
    misalnya: `https://redone.my.id,http://localhost:3000`

    **C. Verifikasi build lokal:**
    Jalankan `npm run build` — pastikan dist/ terbuat tanpa error.
  </action>
  <verify>
    1. `npm run build` — exit 0, folder dist/ ada
    2. `npx tsc --noEmit` — zero errors
    3. `grep -n "includeFiles" vercel.json` — output: `"src/**"`
    4. `grep -n "allowedOrigins" src/api/index.ts` — ada baris split
  </verify>
  <done>AC-1 satisfied: build berhasil, vercel.json + CORS siap production.</done>
</task>

    gunakan `rema-v2`. Catat deployment URL yang dikembalikan.

    **B. Set environment variables di Vercel via API:**

    Ambil project ID dulu:
    ```bash
    curl -s "https://api.vercel.com/v9/projects/rema-v2" \
      -H "Authorization: Bearer vcp_..." | node -e "..."
    ```

    Lalu set semua env vars (production):
    - DATABASE_URL
    - JWT_SECRET=rema_jwt_secret_2025_production_change_me
    - R2_ACCOUNT_ID=5d7b90b431524de3d18b57355b564dfe
    - R2_ACCESS_KEY_ID=52d89ce840e38cae6d2c9c6ca840a107
    - R2_SECRET_ACCESS_KEY=646ea0ab28f8393ed433f4fe41eef3f8a0918f85d1d3cc3f5574956f2af07692
    - R2_BUCKET_NAME=rema-v2
    - R2_PUBLIC_URL=https://storage.jisoi.net
    - CORS_ORIGIN=https://redone.my.id,http://localhost:3000

    Redeploy setelah env vars terset agar production menggunakan nilai baru.

    **C. Tambah custom domain ke Vercel project:**

    ```bash
    curl -s -X POST "https://api.vercel.com/v10/projects/rema-v2/domains" \
      -H "Authorization: Bearer vcp_..." \
      -H "Content-Type: application/json" \
      -d '{"name": "redone.my.id"}'
    ```

    Catat verification value yang dikembalikan (CNAME atau A record value).

    **D. Tambah DNS A record di Cloudflare untuk redone.my.id:**

    Gunakan Cloudflare API (zone `e6d0b79757d9083a758ebea078185c62`, token
    `cfut_c9zT19e8lV6RmHTNVflbUBh66BdjszAFurDNKylT94083a36`):

    ```bash
    # A record root domain → Vercel IP
    curl -s -X POST "https://api.cloudflare.com/client/v4/zones/e6d0b79757d9083a758ebea078185c62/dns_records" \
      -H "Authorization: Bearer cfut_..." \
      -H "Content-Type: application/json" \
      -d '{"type":"A","name":"redone.my.id","content":"76.76.21.21","proxied":false,"ttl":1}'

    # CNAME www → cname.vercel-dns.com
    curl -s -X POST "https://api.cloudflare.com/client/v4/zones/e6d0b79757d9083a758ebea078185c62/dns_records" \
      -H "Authorization: Bearer cfut_..." \
      -H "Content-Type: application/json" \
      -d '{"type":"CNAME","name":"www","content":"cname.vercel-dns.com","proxied":false,"ttl":1}'
    ```

    Catatan: `proxied: false` (grey cloud) agar Vercel bisa provisioning
    SSL cert sendiri. Jangan aktifkan Cloudflare proxy untuk record ini.
