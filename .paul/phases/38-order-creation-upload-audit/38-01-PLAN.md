<objective>
## Goal
Hardening backend POST /api/orders: fix express.json() limit 100KB → 2MB, tambah mitraId ownership check, credit limit backend check, dan field validation dasar.

## Purpose
Saat ini POST /api/orders tidak memvalidasi field apapun selain role. Mitra bisa (a) kirim request body dengan mitraId mitra lain, (b) bypass credit limit check, (c) submit order kosong tanpa items. Express.json() default 100KB bisa menyebabkan 413 error untuk order dengan banyak items dan URLs.

## Output
- `src/api/index.ts` — express.json limit naik ke 2MB
- `src/api/routes/orders.ts` — POST handler dengan ownership + credit limit + field validation
</objective>

## AC-1: express.json() Limit Dinaikkan
```gherkin
Given backend Express API berjalan
When POST /api/orders dikirim dengan JSON body yang mendekati atau melebihi 100KB
Then request diproses (tidak ditolak dengan 413 Payload Too Large)
```

## AC-2: mitraId Ownership Enforced
```gherkin
Given user mitra A sedang login
When mitra A mengirim POST /api/orders dengan mitraId milik mitra B
Then response adalah 403 Forbidden dengan pesan "mitraId tidak sesuai akun Anda"
```

## AC-3: Credit Limit Backend Check
```gherkin
Given mitra memiliki creditLimit yang sudah dikonfigurasi
When mitra mengirim POST /api/orders yang akan melebihi creditLimit
  (outstanding orders isBilled=false + totalAmount order baru > creditLimit)
Then response adalah 400 Bad Request dengan pesan kredit limit exceeded
```

## AC-4: Field Validation
```gherkin
Given request POST /api/orders tanpa items (atau items kosong)
When request dikirim
Then response adalah 400 Bad Request dengan pesan "Items pesanan tidak boleh kosong"
```

```gherkin
Given request POST /api/orders dengan type selain 'online' atau 'offline'
When request dikirim
Then response adalah 400 Bad Request dengan pesan "Tipe pesanan tidak valid"
```

    ```ts
    const mitra = await getMitraForUser(req.user.sub);

    ```

    2. **Field validation** (sebelum insert):
    ```ts
    const { items, ...orderData } = req.body;

    // Validate type
    if (!['online', 'offline'].includes(orderData.type)) {
      return res.status(400).json({ error: 'Tipe pesanan tidak valid' });
    }

    // Validate items
    if (!Array.isArray(items) || items.length === 0) {
      return res.status(400).json({ error: 'Items pesanan tidak boleh kosong' });
    }
    ```

    3. **mitraId ownership check**:
    ```ts
    if (orderData.mitraId && orderData.mitraId !== mitra.id) {
      return res.status(403).json({ error: 'mitraId tidak sesuai akun Anda' });
    }
    // Enforce correct mitraId dari JWT (bukan dari body)
    orderData.mitraId = mitra.id;
    ```

    4. **Credit limit check** (jika mitra punya creditLimit):
    ```ts
    if (mitra.creditLimit) {
      const outstandingOrders = await db.select({ totalAmount: orders.totalAmount })
        .from(orders)
        .where(and(eq(orders.mitraId, mitra.id), eq(orders.isBilled, false)));
      const outstanding = outstandingOrders.reduce((sum, o) => sum + (o.totalAmount || 0), 0);
      const newTotal = orderData.totalAmount || 0;
      if (outstanding + newTotal > mitra.creditLimit) {
        return res.status(400).json({
          error: `Tagihan berjalan: ${outstanding.toFixed(0)}. Order baru: ${newTotal.toFixed(0)}. Melebihi limit kredit: ${mitra.creditLimit.toFixed(0)}`,
          code: 'CREDIT_LIMIT_EXCEEDED',
        });
      }
    }
    ```

    5. Lanjutkan ke insert seperti semula (`if (!orderData.id) orderData.id = ...`).

    **Jaga agar compensating delete tetap ada** setelah insert orderItems — jangan hapus logika itu.
