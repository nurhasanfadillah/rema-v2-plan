<objective>
## Goal
Halaman **Daftar Pesanan** (`/orders`) mendapat filter **status cetak DTF**: satu baris chip "Semua DTF · Belum Cetak · Sudah Cetak · Tanpa DTF" (masing-masing dengan jumlah pesanan) di bawah filter status, yang berkombinasi (AND) dengan filter status dan pencarian yang sudah ada.

## Purpose
Tim produksi/operasional dan mitra dapat langsung menyaring pesanan yang item custom-nya masih menunggu cetak DTF — atau yang sudah selesai dicetak — tanpa membuka detail pesanan satu per satu (permintaan user 2026-10-23).

## Output
- Modul baru `src/components/orders/dtf-filter/`: tipe, fungsi murni (pengelompokan, penyaringan, penghitungan), komponen chips, dan `index.ts` sebagai public API
- `src/pages/orders/OrdersList.tsx`: penyambungan state, penyaringan, hitungan, dan chips (perubahan minimal)
- Tanpa perubahan API, skema DB, tipe bersama, atau dependency
</objective>

## Keputusan Perencanaan
- **Track:** standard (dipilih user 2026-10-23). Modul baru mengikuti konvensi Phase 42, sehingga menyentuh 4 file baru + 1 file existing — di atas batas 1–2 file untuk quick-fix.
- **Pengelompokan per pesanan** (dipilih user 2026-10-23): Belum Cetak / Sudah Cetak / Tanpa DTF.
  - **Tanpa DTF:** tidak ada item dengan `isCustomLogo`.
  - **Belum Cetak:** ada ≥1 item custom dengan `(dtfStatus || 'belum_cetak') === 'belum_cetak'` — ekspresi yang persis sama dengan guard "Press Sablon" di `OrderDetail.tsx:100`, sehingga filter dan guard tidak pernah berbeda. Pesanan parsial (sebagian sudah, sebagian belum dicetak) ikut di sini.
  - **Sudah Cetak:** punya item custom dan tidak satu pun yang belum cetak. Item polos tidak mempengaruhi.
  - Sumber kebenaran = `items[].isCustomLogo`, bukan `order.hasCustomLogo` (flag level pesanan).
- **Kontrol:** satu baris chip, bukan dropdown + bottom sheet kedua — kode filter status yang ada tidak disentuh; layout sama untuk mobile dan desktop, chip membungkus bila sempit.
- **Hitungan chip:** lingkup role + filter status terpilih, tanpa pencarian, sehingga Belum + Sudah + Tanpa = Semua DTF. Hitungan opsi filter status tidak diubah (tetap tidak memperhitungkan filter DTF — selaras dengan perilakunya terhadap pencarian).
- **Cakupan:** hanya `/orders`; chip tersembunyi di `/orders/drafts` (sama seperti filter status). Berlaku untuk semua role yang melihat halaman ini.
- **Hanya frontend:** `GET /api/orders` sudah mengirim `items[].isCustomLogo` dan `dtfStatus` ke semua role. Kolom DB `dtf_status` nullable, jadi item polos/data lama bisa bernilai `null` di runtime walau tipenya `?:`.
- **Konvensi:** seperti Phase 42 — folder + `index.ts`, file kebab-case, named export, tanpa `any`, `import type` di fungsi murni, logika di fungsi murni (bukan di komponen).
- **Catatan kode existing:** `OrdersList.tsx` sudah memiliki `React.useEffect` setelah `if (!user) return null` (±line 97). Tidak diperbaiki di phase ini; state baru wajib ditaruh di atas early return.

## AC-1: Pengelompokan DTF per pesanan
```gherkin
Given pesanan dengan kombinasi item custom (isCustomLogo = true) dan item polos
When pesanan dikelompokkan berdasarkan status cetak DTF
Then pesanan tanpa item custom (termasuk daftar item kosong) masuk "Tanpa DTF"
And pesanan dengan ≥1 item custom berstatus 'belum_cetak', null, atau kosong masuk "Belum Cetak" (termasuk pesanan parsial)
And pesanan yang semua item customnya 'sudah_cetak' masuk "Sudah Cetak" (item polos tidak mempengaruhi hasil)
And setiap pesanan masuk tepat satu kategori
```

## AC-2: Chip filter tampil di Daftar Pesanan
```gherkin
Given user (admin, staff, operational, atau mitra) membuka /orders
When control bar dirender
Then di bawah filter status tampil baris chip "Semua DTF", "Belum Cetak", "Sudah Cetak", "Tanpa DTF", masing-masing dengan jumlah pesanan
And "Semua DTF" aktif secara default; chip aktif berwarna biru selaras opsi aktif filter status dan ber-aria-pressed="true"
And di viewport 375px chip membungkus ke baris berikutnya tanpa overflow horizontal halaman
And baris chip tidak tampil di /orders/drafts
```

## AC-3: Penyaringan dan kombinasi dengan filter lain
```gherkin
Given daftar pesanan dengan campuran kategori DTF
When user memilih salah satu chip DTF
Then tabel desktop dan kartu mobile hanya menampilkan pesanan berkategori itu
And angka "N Pesanan" dan paginasi mengikuti hasil, dan halaman kembali ke 1
And bila filter status dan/atau pencarian aktif, hasilnya irisan (AND) semuanya
And angka di tiap chip dihitung dari pesanan dalam lingkup role + filter status terpilih (tanpa pencarian), dengan Belum Cetak + Sudah Cetak + Tanpa DTF = Semua DTF
And memilih "Semua DTF" mengembalikan daftar seperti semula
```

```gherkin
And src/api/**, src/db/**, src/types.ts, dan OrderDetail.tsx tidak berubah
```
